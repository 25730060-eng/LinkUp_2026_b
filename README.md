## PRD (제품 요구사항)

> 3·4주차 팀 문서(문제 정의·Must 기능)와 다르면 그 문서 기준으로 고쳐 주세요. 아래는 현재 코드와 작업 내용에서 정리한 초안입니다.

### 1. 문제와 목표
- 문제: 자녀·손주를 사칭한 메신저 사기 메시지를 받은 사람이 진짜인지 판단하기 어렵고, 의심될 때 무엇을 해야 할지 모른다.
- 목표: 받은 메시지를 확인해 비슷한 유형과 지금 해야 할 일을 알려 주고, 같은 유형의 사례와 신고처를 보여 준다.

### 2. 대상 사용자
- 50~60대 이용자(카카오톡류 메신저 사용). 큰 글씨, 단순한 흐름, 전화 연결이 쉬워야 한다.

### 3. 핵심 기능 (Must)
| 번호 | 기능 | 상태(v0.5) |
|---|---|---|
| 1 | 의심 메시지 붙여넣기와 유형 확인 | 화면 구현, 유형 판별 로직은 미구현 |
| 2 | 유형별 지금 해야 할 일 안내, 긴급 신고(112·1332) 전화 연결 | 화면 구현(고정 문구) |
| 3 | 비슷한 사례 목록: 검색·유형·조건 필터·정렬 | 구현 |
| 4 | 사례 상세와 출처 링크 | 구현(출처 주소 일부 준비 중) |
| 5 | 마이페이지(저장한 사례) | 화면만(저장 기능 미구현) |

### 4. 범위 제외
- 로그인·회원가입, 서버 저장, 외부 API 연동(현재 미사용)
- 사기 여부의 확정 판단(결과는 "참고용"으로만 표시)

### 5. 데이터와 개인정보
- 사례는 `data/cases_all.json`(저장 JSON). 실제 사례는 출처·기준일·확인일을 기록하고, AI 보완 데이터는 화면에 "AI 보완"으로 표시한다.
- 입력한 메시지 원문은 저장하지 않는다(화면에만 표시).

### 6. 화면 구성(IA)
홈(#home) · 메시지 확인(#check) · 확인 결과(#result) · 사례(#cases) · 사례 상세(#detail) · 마이페이지(#saved)

### 7. 이후 계획
- 10주차: ID 기반 상세보기, 목록 복귀 시 조건 유지, 예외 처리
- 11주차: LocalStorage 저장(저장 사례 등)
- 유형 판별 로직(`rules.json` 활용), 출처 주소 보완
